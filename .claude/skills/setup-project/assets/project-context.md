# Project context

## Product and domain

Record the confirmed purpose, audience and domain terms.

## Architecture and conventions

Record real components, their responsibilities and confirmed project-specific
conventions, with local references when available.

For each confirmed constraint relevant to the project, record its scope and
components, allowed or forbidden dependency or responsibility, source and
rationale if known. Record explicit exceptions and their scope, and the existing
tests or static checks that enforce it, if any. Mark undocumented or unresolved
boundaries as pending; absence of a rule or check is not confirmation that it
does not apply. Do not invent layers, dependencies, exceptions or commands.

## Development environment

Record applicable setup, dependencies and services. For authentication, mention
only mechanisms and environment variable names, without credential values.

## Validation and delivery

Record details needed to interpret the commands and delivery workflow configured
in the profile. Distinguish confirmed requirements from pending items.
